# 同序 · TONGXU

把企业微信群里的办公请求，交给机主电脑上的 Codex 处理。

同序是一套 Windows 桌面工作台与本地后台服务。群成员可以提交文档、编程和资料处理任务；机主在桌面端登记成员、审查任务、管理文件，并决定哪些软件操作可以执行。目前接入的是 **企业微信 + Codex CLI**，不是已经支持多平台的通用成品。

这个项目首先要解决的，是共享一台电脑时的权限问题：**允许成员使用 AI 办公，不应等于把机主整台电脑交出去。** 所以，同序为任务建立独立工作副本，由宿主程序校验身份、文件范围和结果发布，再把限制传给 Codex 原生权限机制。安全边界不能只靠提示词要求模型“自觉”。

> 当前发布版本为 **1.0.0**。仓库提供干净源码与占位示例，Release 提供联网安装器和编译好的程序包，不包含部署者的配置、群成员名单、文档、对话、登录凭据或运行记录。当前仍需按自己的环境验收。

## 下载与安装

到 [最新正式版](https://github.com/iwanttobeacmer666-ctrl/TONGXU/releases/latest) 选择适合的下载方式：

| 下载内容 | 适合谁 | 需要自己准备什么 |
| --- | --- | --- |
| `TONGXU-Setup-1.0.0.exe` | 希望通过窗口安装的 Windows x64 用户 | Codex CLI、企业微信接入信息；安装器会检测 .NET，缺少时经确认后下载兼容的 .NET 10 Desktop Runtime。 |
| `Tongxu-1.0.0-win-x64.zip` | 希望直接解压运行的用户 | 自行安装 .NET 10 Desktop Runtime（x64）；无需 Go 或 .NET SDK。 |
| `TONGXU-Source-1.0.0.zip` / GitHub Source code | 希望自己编译或修改源码的用户 | 自行安装 Go 1.25.0 或满足模块要求的版本、.NET 10 SDK，并准备 Go 模块依赖。 |

**安装器流程**：双击 → 选择安装位置 → 查询最新正式版 → 检测运行环境 → 缺少时确认下载安装 → 下载并校验同序程序 → 创建快捷方式 → 打开同序。

首次打开后，在“连接与运行”配置 Codex CLI、企业微信机器人、机主及群 ID，在目录设置中选择工作区，然后完成专用 CLI 登录并手动启动服务。已有的原生 CLI 支持自动发现，也可以手动选择 EXE。保存后的配置下次继续使用。

安装器的 `1.0.0` 是安装器自身版本，**不锁定同序程序版本**。以后正常发布 `1.0.1` 等新版本，只要安装协议和运行环境仍兼容，原安装器会获取 GitHub 标记的最新正式版，不必每次重新制作安装器。首次下载、重新安装或升级都需要能访问 GitHub；缺少最新程序包或校验信息时会停止，不会偷偷退回旧版。

直接使用程序 ZIP 时，先完整解压，再打开 `bin\desktop\tongxu.exe`，不要只复制一个 EXE。程序文件与用户数据分开，安装布局将配置保存在当前用户的 `%LOCALAPPDATA%\Tongxu\runtime`，工作目录仍可在设置中选择 D 盘。升级前先从托盘退出同序；源码部署不会自动迁移进安装版。

发布包目前未做发行者代码签名，也尚未完成干净 Windows 上的安装、升级、卸载及真实群场景验收。本地编译和隔离测试不能代替这些检查。

详细操作见 [Windows 工作台使用指南](docs/windows-desktop.md)，本次发布内容见 [1.0.0 发布说明](docs/release-1.0.0.md)。

## 可以做什么

- **群里提交任务**：在已登记的企业微信群中请求处理文档、写代码、运行已有工具，读取允许访问的资料并返回结果。具体文件格式是否可用，取决于本机安装的软件。
- **按人保存文件与会话**：成员的文件区和 Codex 会话分别管理；群公共区提供共享资料。支持查看上下文、压缩自己的会话和开始新会话。
- **机主管理**：六个桌面页面分别处理连接、群与成员、停用用户、任务审查、文档和设置。可以查看公开执行输出、停止任务、管理成员和核对文件删除清单。
- **控制后台运行**：打开界面不会自动启动群服务。运行时关闭窗口会隐藏到托盘；托盘只提供“打开主界面”“退出”。选择退出会停止服务及其任务，确认服务结束后关闭应用。
- **调整桌面外观**：跟随系统、浅色和黑灰色深色模式，可手动选择并记住；支持背景图和十种界面语言。
- **分离程序和个人数据**：安装布局中的配置、登录与工作区独立保存；覆盖程序文件不会迁移个人资料。
- **更新检查与任务排空**：设置中已有 GitHub 更新检查、版本说明和后台暂停接收任务的逻辑。桌面内的安装交接仍按 MSI 协议设计，本次 Release 提供 ZIP；需要升级时可重新运行联网安装器，暂不承诺 ZIP 发布具有桌面内自动升级能力。

消息平台与 Agent 在界面中使用下拉框，但当前分别只有企业微信和 Codex CLI 一个选项。没有实现的接入不会出现在可选列表里。

## 为保护机主电脑做了哪些限制

这些是代码中的约束与设计目标，不是“任何环境都绝对安全”的承诺。部署前仍须验证所用 Codex 版本的 Windows 原生权限实现。

| 边界 | 当前处理方式 |
| --- | --- |
| 谁能使用 | 后端按群与稳定用户 ID 校验登记、启用状态；聊天文字不能把自己变成管理员。机主是唯一全局管理员。 |
| 能读写哪里 | 文件系统权限默认拒绝。每项任务只有自己的工作副本可写；普通成员拿到的公共区为只读，工具目录也按明确的只读清单授权。机主个人文件目录不会因为接入群聊就自动开放。 |
| 是否直接编辑持久资料 | 原生任务操作临时副本。持久文件的读取、写回、覆盖和删除由外层校验归属、目标及版本后处理，而非让模型任意选择宿主绝对路径。 |
| 能否访问别人的资料 | 普通成员不能管理其他成员文件。管理员也需要明确目标成员及文件范围，不会默认把全群文件都装进一次任务。 |
| 能否读到登录信息 | 使用项目专用 `CODEX_HOME`，任务文件系统配置拒绝访问该认证目录；对子进程过滤包含 TOKEN、KEY、SECRET、PASSWORD 等名称的环境变量及机器人凭据。专用登录不复用机主日常工作区里的认证目录。 |
| 能否随意联网 | 普通原生执行在默认配置下断网。网页与下载通过受控工具处理；软件、脚本与未知类型等请求按分类进入审批。显式放行域名会改变网络边界，需要机主核对。 |
| 能否装软件 | 普通成员可以提出请求，不能批准自己。支持的安装操作要经管理员审批，并限制在对应的软件区，不把请求当成修改机主系统环境的授权。 |
| 删除、覆盖如何确认 | 当前发起人明确指定对象的操作，在校验权限和版本后处理；助手自行决定或目标不明确的破坏性操作仍需原发起人确认。管理员的软件审批不能替代文件发起人的确认。 |
| 本机管理入口 | 使用受限的 Windows 命名管道，不为管理功能开放 TCP 监听端口。核对用户令牌、进程及有限操作集合，拒绝受限令牌和 AppContainer 客户端。 |
| 停用与停止 | 撤销新请求，取消相应排队和执行任务，使待确认操作失效。清理未确认时不显示为完成，也不把“停止请求已接受”等同于进程已退出。 |

代码入口可从 [原生权限配置](backend/groupassistant/boundary.go)、[任务运行器](backend/groupassistant/native.go)、[工作副本](backend/groupassistant/snapshot.go) 和 [本机管道校验](backend/cmd/group-assistant/operator_pipe_windows.go) 开始阅读。

**文件区隔离不等于群聊保密。** 机器人发回群里的文字和文件，群内其他人仍可能看到。也不能把专用登录误解成“每位成员拥有独立的模型账号”：群任务使用的是机主为项目配置的登录与额度。

## 从源码构建前需要准备

当前桌面与正式原生任务路径面向 Windows。

| 项目 | 要求 |
| --- | --- |
| 桌面构建 | .NET 10 SDK，以及相应的 Windows Desktop 引用/运行环境。源码目标为 `net10.0-windows`。 |
| 后端构建 | Go 1.25.0 或满足模块要求的较新本机版本。 |
| Agent | 已安装的 Windows 原生 `codex.exe`，且通过项目的兼容与权限握手检查。找到文件不等于版本兼容。 |
| Windows 任务边界 | 当前运行器要求 `windows.sandbox=mxc`；不能用关闭沙箱或放宽权限来绕过检查。 |
| 群接入 | 可使用的企业微信机器人凭据、机主稳定用户 ID 和目标群 ID。 |
| 办公工具 | 按任务需要自行准备 Python、Node.js、Office/LibreOffice 等；本项目不会替你自动装好全部工具。 |

无需 Docker。脚本不会自动安装或升级 SDK、Codex，也不会自动调整系统安全设置。

## 从源码构建

下载仓库 ZIP 并解压到专用目录，例如 `D:\TONGXU`。下面的路径只是示例，不应复制任何人的现有登录目录或运行配置。

### 1. 准备 Go 依赖与后端

首次使用需要下载 Go 模块依赖。以下命令中的 `go mod download` 会联网，请在你允许下载依赖的环境中执行。已有依赖缓存时可以跳过下载。

在项目根目录打开 PowerShell：

```powershell
$project = (Get-Location).Path
$backend = Join-Path $project 'backend'
New-Item -ItemType Directory -Path (Join-Path $project 'bin') -Force | Out-Null
Push-Location $backend
go mod download
go build -o (Join-Path $project 'bin\group-assistant.exe') ./cmd/group-assistant
Pop-Location
```

这里使用你已有的 `go`，不安装编译器。若构建失败，先查看原始错误，不要为了通过构建关闭权限检查。

### 2. 构建桌面程序

仍在项目根目录执行：

```powershell
.\Build-Desktop.ps1 -DotNet 'D:\dotnet\dotnet.exe'
```

把参数换成自己实际安装的 .NET SDK 路径。桌面工程没有第三方 NuGet 包，构建脚本清空包源；缺少本地框架引用时会停止，不会临时联网补装。

成功后，桌面入口为 `bin\desktop\tongxu.exe`。请保留旁边的 DLL 和 JSON 运行文件，不要只把 EXE 拿到别处。`bin\group-assistant.exe` 是后台服务，和桌面入口用途不同，需要保留。

项目还保留 `build.ps1 -Go <已有 go.exe 路径>`，用于后端回归、静态检查和构建。该脚本使用项目内离线模块缓存；空白下载不自带这份缓存，因此它不是首次联网下载依赖的向导。

### 3. 创建自己的本地配置

```powershell
Copy-Item .\config.group-assistant.example.json .\config.group-assistant.json
```

编辑新文件，替换 `YOUR_USER_ID`、`YOUR_GROUP_ID` 及示例路径。文档目录、任务临时目录、软件目录、状态目录应为独立的本地子目录；`CodexCommand` 要指向真实的原生 `codex.exe`，专用 `CodexHome` 应放在这个项目自己的 `runtime\codex-home` 下。

示例中的 `ToolRoots` 默认是空的。如果任务需要访问已有工具，机主应逐项核对并显式授予所需工具目录的只读权限，不要把整个磁盘、用户目录或个人认证目录放进去。

随后运行：

```powershell
.\Configure-GroupAssistant.ps1
```

按提示保存机主 ID、群、成员、机器人 ID/Secret，以及本机程序与目录。这个入口只配置，不启动群连接；输入 Secret 时不会把它显示为普通文本。保存的机器人 Secret 使用 Windows 用户范围的加密存储，但这不保护已经被接管的 Windows 账号。

### 4. 登录项目专用 Codex

```powershell
.\Login-Codex.ps1
```

该入口只管理项目专用登录，不会启动群服务。也可以在桌面“连接与运行”页点击“专用 Codex 登录”。首次部署应先完成配置，再登录，再启动服务。

### 5. 启动桌面并做一次小任务

打开 `bin\desktop\tongxu.exe`，在“连接与运行”核对状态和脱敏凭据，再点击“启动服务”。只有服务启动并连接后，已登记且启用的群成员才能开始工作。

先用无敏感信息的测试群和一个小文件验证：

1. 在“群与成员”登记自己的稳定 ID 和测试群，确认启用状态。
2. 在群里 @机器人发送 `/help`，再提交一项简单任务，例如生成一份示例文本。
3. 在“任务审查”核对公开执行输出与结果，在“文档管理”确认文件归属。
4. 尝试越界读取一个预先准备的无敏感测试目录，确认被拒绝；再验证停止、停用和恢复流程。不要用真正的隐私文件做权限探针。

在另一位成员、其他群、附件和受控软件操作尚未验收前，不要直接扩大到正式多人办公。

## 日常操作

| 位置或指令 | 用途 |
| --- | --- |
| 连接与运行 | 启动/停止全部群服务，查看平台与 Agent 状态，修改连接配置。 |
| 群与成员 / 已停用用户 | 登记、搜索、启停成员与群；恢复时核对清理状态。 |
| 任务审查 | 筛选任务、查看公开输出、停止选中的任务；不展示模型内部思考。 |
| 文档管理 | 查看权限允许的文件、分页阅读、保存副本、核对清单后删除。 |
| 设置 | 切换语言、颜色模式和背景；停机后编辑服务目录；查看更新状态。 |
| `/help` | 查看当前支持的指令与权限。 |
| `/model`、`/thinking` | 查询模型和思考强度；只有管理员能修改当前群设置。 |
| `/context`、`/compact`、`/new` | 查看、压缩或重置自己的会话关联。压缩可能消耗模型额度。 |
| `/token` | 查询共享账号返回的额度窗口；不是个人剩余 token 余额。 |
| 管理员 `/tasks`、`/stop` | 在当前群查看或停止任务。桌面端提供跨群审查。 |

服务运行时点窗口关闭会隐藏到托盘。想结束运行，请从托盘选择“退出”；只是重新打开窗口，不要再启动另一份程序。服务未运行时，关闭窗口会直接退出。

删除前请核对具体对象。临时区清空需要全局空闲并看完清单；它不是“帮某一个人删掉几个临时文件”的操作。更换目录只改变后续位置，不会自动搬迁或删除旧文件。

## 目前的不足

- **安全依赖实际运行环境。** 原生 Codex/MXC 的版本与接口变化可能影响启动或权限边界。`BoundaryVerified` 是运行选择标志，不是安全审计报告；启动通过也不代表完成所有隔离验收。
- **还不能承诺完整多人生产验收。** 本地隔离测试验证过合成平台、成员与任务流程；真实多群、第二位成员、附件、软件下载/安装/卸载和远程资源的组合边界仍需独立验证。
- **不是虚拟机，也没有完整资源配额。** 有任务排队、超时和进程生命周期处理，但没有完整的 CPU、内存、进程数量及实时磁盘配额。不能把恶意代码隔离能力当作已解决的问题。
- **共享账号与群内隐私仍有限制。** 群任务共用专用登录与额度；群回复可被群成员看到。文件隔离无法把公开群消息变成私聊。
- **平台与系统支持有限。** 当前正式路径是 Windows、企业微信和 Codex CLI；发行安装器仅面向 Windows x64，其他平台接入和跨平台桌面尚未提供。Apps/MCP 等远程工具权限也没有完成完整验收。
- **任务历史不是持久审计日志。** 当前只在内存保留最近 50 个已结束任务、每项最多 40 条事件，重启后不保留这份历史。
- **错误提示与部署体验仍需改善。** 例如“程序或启动检查未通过”会合并多种原因；Codex 更新后，保存的原生 EXE 路径可能失效，需要重新选择。空白源码包不等于已经登录、配好工具的即用环境。

首次使用请在专用目录与无敏感测试资料上完成验收，再逐步开放给成员。不要用授予管理员权限、开放整个用户目录或关闭沙箱的方式消除报错。

## 常见问题

**每次更新都要重新发布安装器吗？**

不需要。日常更新编译程序并发布新的正式 Release，附上对应版本的 `Tongxu-<版本>-win-x64.zip` 即可。旧安装器在运行时查询最新正式版。只有下载来源、安装协议、运行环境主版本或安装器本身有变化时，才需要新安装器。[安装发布约定](setup/ONLINE.md) 说明了包名和校验要求。这里不等于已安装的程序会自行更新。

**为什么源码包需要 Go，程序 ZIP 不需要？**

Go 用于把后端源码编译成 EXE。源码用户需自己准备编译工具；Release 程序包里的后端已经编译完成。C# 桌面也有类似区别：源码构建需要 .NET SDK，运行编译后的桌面需要 .NET Desktop Runtime。安装器负责检测并经用户同意后准备运行环境，不安装开发 SDK。

**为什么启动时提示 Codex 检查失败？**

先检查保存的 `codex.exe` 是否仍存在，再核对专用登录和原生权限握手。桌面版 Codex 更新可能改变其内置 CLI 路径。当前提示不够细，不能仅凭这句话断定登录失效。

**服务运行中，但机器人或 Agent 不可用？**

本地服务、企业微信连接和 Agent 状态分别展示。服务活着不代表群已连上；Agent 程序就绪也不代表真实模型调用已经验证。检查对应一项，不要盲目重复启动。

**为什么请求停止后没有立刻显示成功？**

取消任务、关闭进程和释放服务锁需要时间。程序会等待确认；清理失败或超时会保留提示。已经写回的结果不会因为停止而自动回滚。

**可以把自己运行后的目录重新上传吗？**

不要直接上传整个目录。实际配置、`runtime`、工作资料、登录目录、日志和会话都属于本地部署数据。仓库提供忽略规则，但忽略规则不是内容审计；发布前仍应核对暂存区和历史，尤其不要用强制添加把被忽略的数据传上来。
